# Generated UI anti-patterns

Treat these as review prompts. A treatment is a problem when it obscures the work or has no purpose, not merely because it is common.

| Pattern | Review and better direction | When it can fit |
| --- | --- | --- |
| Card soup | Remove containers that add no conceptual grouping; use layout, labels, and separators. | Independent entities, distinct tasks, or genuinely separate summaries. |
| Excessive nested containers | Flatten repeated borders and padding that shrink the workspace. | A clear parent-child relationship needing separate interaction or boundaries. |
| Pill soup | Present ordinary metadata as text; reserve chips for meaningful states or selections. | Status differentiation, removable selections, compact filter tokens. |
| Giant headings | Reduce headings that push useful workspace below the fold. | Editorial or marketing emphasis, deliberate consumer storytelling. |
| Arbitrary gradients/glows/glass | Remove unrelated purple/blue gradients, blurred orbs, gradient text, and translucent effects. | Established branding or a deliberate visual concept with readable contrast. |
| Excessive shadows | Use elevation sparingly and consistently. | Floating menus, dialogs, or surfaces whose layering must be understood. |
| Over-rounded geometry | Choose radius by component role and product vocabulary. | A coherent friendly visual identity or established component system. |
| Meaningless metric cards | Replace decorative counts with actionable summaries and useful context. | Metrics tied to decisions, with units, timeframe, and comparison. |
| Ornamental charts | Prefer direct values or tables when no meaningful relationship exists. | Trends, distributions, comparisons, or relationships users need to understand. |
| Generic welcome copy | Replace filler with task-specific information or remove it. | Onboarding or a greeting that communicates relevant context. |
| Icon overload | Remove icons that repeat clear text or create ambiguity. | Recognizable navigation, action discovery, or status support. |
| Low operational density | Reduce empty space that hides queues, records, or exceptions. | Infrequent tasks, touch-first use, or a focused flow needing breathing room. |
| Inconsistent spacing | Reuse tokens and distinguish related from separate groups. | Intentional editorial composition with a legible rhythm. |
| Inconsistent button hierarchy | Establish a clear primary action and restrained supporting actions. | Separate independent regions each requiring a local primary action. |
| Random accent colors | Assign colors semantic roles rather than coloring every widget. | Stable categories or a documented multi-accent brand system. |
| Identical primary/secondary actions | Distinguish consequence and priority through established treatments. | Peer actions with genuinely equal importance. |
| Giant or cramped modals | Move complex workflows to a page or panel; bound dialog content and retain usable actions. | A focused context-preserving task that needs substantial preview space. |
| Poorly grouped forms | Group related fields, choose widths and controls by content, and place validation near errors. | A short linear form where a single column is clearest. |
| Blind mobile card conversion | Preserve comparison and critical actions using scrolling, column priority, or details. | Independent records that users inspect one at a time. |
| Fake complexity | Remove redundant tabs/filters, empty panels, and invented functionality. | Real distinct workflows, filtering needs, or permissions requiring separation. |
| Stock dashboard grid | Start with users' actual decisions instead of four cards, charts, and an activity feed. | An analytics task whose data and decisions justify that arrangement. |

An explicit user direction or existing identity can justify these patterns. Preserve it while improving hierarchy, usability, and coherence; do not substitute personal taste for the requested design.
