# Durable project context

Read existing project guidance before proposing new documents. Respect repository locations such as `docs/DESIGN.md`; filenames alone do not establish authority or erase conventions already present in code.

For projects large enough to benefit, recommend:

- **PRODUCT.md:** users, jobs/tasks, primary workflows, product type, important constraints, and information priorities.
- **DESIGN.md:** project visual identity, typography, color, spacing, component rules, density, navigation, responsive behavior, reference screenshots/scopes, and intentional deviations.

Use these as durable project-specific sources, not copies of Jevon UI or Impeccable manuals. Keep route-specific exceptions scoped and describe the actual product rather than aspirational generic rules.

Neither document is required for every small project. Do not create them automatically unless the requested work or project benefits; extend existing documentation instead of introducing competing specifications. Missing files do not justify redesign or block a focused fix.

Impeccable may read these files and offer context/documentation workflows. Select those workflows deliberately; their file conventions are not a reason to relocate or overwrite established project guidance as a side effect.
